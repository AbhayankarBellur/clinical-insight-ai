# Intuition — Capacitor APK Build Guardrails

## Purpose
This document provides exact guardrails for generating Android APKs from this codebase using Capacitor. The APK will use Vercel-hosted URLs for all backend operations (auth, AI, storage). **No codebase logic should be modified** — only Capacitor wrapper configuration is allowed.

## CRITICAL GUARDRAILS — DO NOT VIOLATE

### 1. No Backend Code Changes
- **DO NOT** modify any files in `supabase/functions/`
- **DO NOT** modify `src/integrations/supabase/client.ts` (auto-generated)
- **DO NOT** modify `src/integrations/supabase/types.ts` (auto-generated)
- **DO NOT** modify `src/integrations/lovable/index.ts` (auto-generated)
- **DO NOT** modify `.env` (auto-generated by Lovable Cloud)

### 2. No Authentication Changes
- Google OAuth is managed by Lovable Cloud auth bridge
- **DO NOT** add or modify any `supabase.auth.signInWithOAuth` calls
- **DO NOT** add manual Google OAuth client IDs or secrets
- **DO NOT** modify `src/hooks/useAuth.tsx`
- **DO NOT** modify `src/pages/Login.tsx`

### 3. No AI/LLM Request Changes
- The edge function `supabase/functions/diagnose/index.ts` handles AI requests
- **DO NOT** modify the system prompt, user prompt, or response parsing
- **DO NOT** change the AI model or API endpoint
- **DO NOT** modify `src/lib/parseDiagnosis.ts`

### 4. No UI Behavior Changes
- **DO NOT** modify form validation schemas in `PatientForm.tsx`
- **DO NOT** modify diagnosis result rendering in `DiagnosisResults.tsx`, `ResultCard.tsx`, `FormattedContent.tsx`
- **DO NOT** modify the doctor config hierarchy in `src/data/medicalHierarchy.ts`
- **DO NOT** modify `src/context/DiagnosisContext.tsx`

### 5. No Storage/DB Changes
- **DO NOT** modify `src/lib/diagnosisStorage.ts`
- **DO NOT** create new Supabase migrations
- **DO NOT** modify RLS policies

### 6. Environment Variables
- All secrets (`LOVABLE_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, etc.) are managed server-side via Lovable Cloud
- **NEVER** hardcode any secret in the client-side codebase
- The only client-side env vars are `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (these are publishable/safe)

### 7. Branding
- App name is **"Intuition"** — not "Lovable"
- Favicon is `public/favicon.jpeg`
- All print output headers say "Intuition — Clinical Decision Support Report"
- **DO NOT** add any "Lovable" or "Supabase" branding

## Capacitor Setup Instructions

### Prerequisites
- Node.js 18+
- Android Studio with SDK 33+
- Java 17+

### Steps

1. **Clone & Install**
```bash
git clone <your-repo-url>
cd <project-dir>
npm install
```

2. **Install Capacitor**
```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "Intuition" "app.intuition.clinical" --web-dir dist
```

3. **Configure `capacitor.config.ts`**
```typescript
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'app.intuition.clinical',
  appName: 'Intuition',
  webDir: 'dist',
  server: {
    url: 'https://your-vercel-url.vercel.app',
    cleartext: true,
  },
};

export default config;
```

> **IMPORTANT**: Replace `https://your-vercel-url.vercel.app` with your actual Vercel deployment URL.

4. **Add Android Platform**
```bash
npx cap add android
```

5. **Build & Sync**
```bash
npm run build
npx cap sync android
```

6. **Open in Android Studio**
```bash
npx cap open android
```

7. **Generate APK**
In Android Studio: Build → Build Bundle(s)/APK(s) → Build APK(s)

## Allowed Capacitor Modifications

You MAY add these Capacitor-specific changes:
- `capacitor.config.ts` — Capacitor configuration
- `android/` directory — Native Android wrapper (auto-generated by Capacitor)
- Splash screen and app icon assets in `android/app/src/main/res/`
- `AndroidManifest.xml` — for permissions (internet, camera if needed later)

You MAY install these Capacitor plugins:
- `@capacitor/splash-screen`
- `@capacitor/status-bar`
- `@capacitor/app`
- `@capacitor/browser` (for OAuth redirect handling if needed)

## Security Notes

- All API keys are server-side only (edge functions)
- RLS policies enforce user-level data isolation
- Google OAuth is the only auth method — no password-based login
- Patient data follows tiered privacy: transient intake, compressed archival
- 7-day auto-purge on saved diagnoses
